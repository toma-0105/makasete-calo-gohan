# 献立生成の成功率の計測

計測日: 2026-11-18 / 関連 Issue: #378

## 1. 目的

- 献立生成は、1日の合計カロリーが目標の90〜100%に収まるまで最大10回作り直す（収まらなければ、最も目標に近い献立を採用する）
- 何回目で収まったかを数え、カロリー調整の精度を数字で把握する
- 今後ロジックを改修するときに、改修前後を比べる基準にする

## 2. 計測方法

```bash
docker compose exec web bin/rails runner script/measure_menu_success.rb
```

- アプリ本体は変えず、`MenuCalorieRangeSelectorService` の再試行ループをスクリプト内で再現して回数を数える
- 上限回数（10回）と範囲の下限（90%）は、アプリ本体の定数を参照する
- 失敗した場合は、アプリが代わりに表示する「最も目標に近い献立」が、目標を超えたか・90%に届かなかったかで分ける

## 3. 計測条件

| 項目 | 内容 |
|---|---|
| 環境 | 開発環境（Docker） |
| 料理データ | 178件 |
| 目標カロリー | 1200 / 1500 / 2000 / 2500 / 3200 kcal |
| 回数 | 目標カロリーごとに100回（1回につき最大10回生成） |
| アレルギー・お気に入り | なし（すべての料理が候補） |

- 1200kcalは小柄な人の目標を想定して加えた（例: 身長155cm・体重50kg・40歳・女性・座り仕事で約1,240kcal）
- 料理をランダムに選ぶため、実行のたびに数%ほど結果がぶれる

## 5. 考察

### 2000〜2500kcal: 10回以内にすべて収まった

- ただし1回目で収まるのは約半分。最大10回の作り直しが精度を支えている

### 1200kcal: 23%が目標を超えた

- 分量の倍率は1.0倍未満にならない（`PORTION_SCALES_BY_TYPE`。減らす方向の調整がない）
- 毎食に主食・主菜・副菜（一品料理の場合は一品料理と副菜）が付く
- プログラムが選べる範囲で最も軽い献立でも、合計は中央値で約1,250kcalになり、1,200kcal以下の献立が作りにくい

### 3200kcal: 66%が90%（2,880kcal）に届かなかった

- 主食は1.25倍まで（`STAPLE_MAX_PORTION_SCALE`、#134。炭水化物に偏らないための上限）
- 副菜・汁物は常に等倍で、一品料理は26品のうち18品が分量を変えられない
- 最も重い献立でも、合計は中央値で約2,340kcalにとどまり、2,880kcalに届く献立がほとんど作れない

### 利用者への影響

- 失敗したときは最も目標に近い献立が表示されるため、目標1200kcalの人には目標を超えた献立が、3200kcalの人には目標に届かない献立が表示される

※ 最も軽い／重い献立の値は、本スクリプトとは別に、目標を1kcal／100,000kcalにして各300回生成したときの中央値

## 6. 今後の改善候補

#378 ではアプリ本体を変更せず、計測と記録までとした。

- 高い目標の不足: 主食の上限を1.5倍にした場合と比べる（#379）
- 低い目標の超過: 分量を減らす倍率（例: 0.75倍）を加えるなど。別Issueで検討する

## 7. 再計測のルール

- 献立生成のロジックや料理データを変えたら再計測する
- 結果は計測日・料理データの件数とあわせてこのドキュメントに追記し、前回と比べる
